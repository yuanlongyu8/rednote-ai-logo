# 探索与校准经验

以下来自 Spark 长周期探索。左列是实际出现的问题，右列是可迁移机制。具体星星、火种、键帽、黑银配色不自动成为其他产品答案。

| 现象 | 根因 | 校准机制 |
|---|---|---|
| 一开始大量候选，但像通用 AI 图标 | 产品事实与平台调性没有先形成约束 | 先 Ground，再只生成差异真实的方向 |
| 用 S、火焰、气泡、星芒堆叠故事 | 一个图形承担过多隐喻 | 一个主体、一个有效变化；删去不能独立解释的装饰 |
| 材质很完整，设计关系反而看不懂 | 呈现层覆盖了基础图形 | 分开评审母形和材质；母形失败时不继续渲染 |
| 用户说“还是原图，没有变化” | 修改只有不可见的一像素差或缩略图无差异 | 在真实评审尺寸比较；提高可见差异但保持平面关系 |
| 用户说“质感太重、立体感太强” | 连续明暗、厚倒角和投影制造了新层级 | 退回确认母版，只保留窄边、单色色块或局部缎面 |
| 灰蓝背景显脏、抢主体 | 大面积灰阶和颜色承担了主视觉 | 白色为主，色彩只分离键位关系；主体保持第一层级 |
| 生成器局部编辑后整体漂移 | 模型重画了未授权区域 | 用遮罩、SVG 或程序合成；检查补丁外像素差异 |
| 主体与底座连接位置被缩小 | 只看整体“更精致”，忽略指定几何关系 | 锁定连接宽度、进入深度、相对坐标和参考母版 |
| 把所有主体塞进同一个键帽载体 | 混淆可共享背景与方案自身的构形 | 逐方案声明哪些层可复用；独立设计不强行套统一载体 |
| 每种图标都统一加 padding | 把统一场景误解为统一缩放 | 独立形用 contain，完整 App icon 用 full-bleed |
| 背景层没有占满图标 | 组合图把背景当普通图片缩放 | 背景先覆盖最终圆角容器，主体再独立定位 |
| 主体在键盘/键帽背景中过小 | 使用源图内置留白或机械相同比例 | 先裁掉内置留白，再按光学重量设置每方向比例 |
| 手机主屏只有少数方案 | 用代表性样例替代全量检查 | 当前方案 × 背景层形成组合矩阵，逐项生成主屏 |
| 手机主屏除目标 Logo 外都模糊 | 整张屏幕被缩小后再放大或使用低清合成图 | 保留原始清晰主屏，只在原生 slot 替换图标 |
| HTML 讲了太多过程和辩解 | 面向执行者的工作记录直接搬给评审者 | 评审页只留方案、必要理念、差异、风险和决策 |
| 写入了错误 Figma 区域 | 只凭文件名/当前画布推测目标 | 使用用户给定 URL 的 file key 与 node id；写前确认，写后回读 |

## Spark 的关键演进

1. **泛探索**：从 S、火种、气泡、键盘和星芒形成大量方向，暴露“有画面但无产品语义”的问题。
2. **重新定调**：按产品关键词与小红书清晰、简约、一致、易用、灵动的取向，拆开基础图形与外层呈现。
3. **构形收敛**：通过正负形、连接关系和小尺寸检查保留多条方向，不强迫唯一选择。
4. **精确局部修改**：星星衔接位置和三角嘴证明，几何要求明确时应使用确定性合成而不是整图再生成。
5. **背景校准**：键盘背景从灰蓝渐变退回珍珠白，说明“有颜色”必须服从键盘关系和主体层级。
6. **材质校准**：黑色主体从整面材质、关键细节、超轻边缘、可见色块再到黑银缎面，形成“可见但不改变设计关系”的判断尺度。
7. **组合评审**：五个主体与纯白、键盘排列、单键粒三背景组成全量矩阵；不能只做少数组合。
8. **主屏与 Figma**：主屏清晰度、背景满幅、主体比例、全部组合和指定 node 写入成为交付硬要求。

## 反馈优先级

1. 最新明确人工反馈；
2. 已确认版本和禁改范围；
3. 产品事实与小红书取向；
4. 项目内可迁移规则；
5. AI 初始假设与历史默认值。

后来的明确指示可以推翻早期 AI 假设，但不能静默覆盖历史资产。
