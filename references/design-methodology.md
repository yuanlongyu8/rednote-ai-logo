# 两层设计方法论

这是本 Skill 的默认工作逻辑。即使设计师只上传参考图、没有说明方法，Agent 也必须主动按此流程组织工作；不要把方法问题重新抛给设计师。只有缺失信息会实质改变品牌方向、目标场景或授权范围时才提问。

## 顶层模型

Logo 方案拆成两个设计层：

| 层 | 负责什么 | 先判断什么 | 常见错误 |
|---|---|---|---|
| 主体图案层 Subject Mark | 品牌语义、核心轮廓、正负形、比例、姿态、表情、识别点 | 不看背景时是否仍能成立 | 用材质掩盖普通图形；塞入过多隐喻；只剩首字母 |
| 背景层 Background / Base | App icon 容器、键帽/键盘关系、底色、纹理、材质、边界和承托层级 | 去掉主体后是否仍是克制、完整的承载系统 | 抢主体；未铺满；强行把所有主体装进同一载体 |

颜色和材质不是独立的第三层，而是两层各自的属性：主体可以有主体色与局部材质，背景可以有底色、纹理和容器材质。手机主屏、导航、小尺寸、HTML 和 Figma 是验证与交付场景，不是新的设计层。

## 只收到参考图时怎么开始

### 1. 建立 Reference Map

逐张参考标记用途，允许一张图承担多个明确角色，但不能写成笼统的“风格参考”。

| 角色 | 提取内容 | 不复制 |
|---|---|---|
| `subject-geometry` | 主体轮廓、比例、正负形、连接/遮挡 | 原品牌符号和独特图形 |
| `background-structure` | 容器、排列、满幅关系、边界 | 参考中的主体 |
| `material` | 哑光、缎面、软触、轻微层次 | 强光效、水印和版权元素 |
| `color` | 色相角色、明度和饱和度关系 | 未经判断的整套配色 |
| `composition` | 主体与背景的占比、位置、连接深度 | 不适合目标场景的画布比例 |
| `context` | 手机主屏、同类 App 重量、展示距离 | 参考图中的目标 Logo |

先写一句话说明每张参考“用于哪一层、学习什么、明确不复制什么”。

### 2. 建立当前真相

检查已有项目、历史版本和人工反馈；列出：

- 已确认主体；
- 已确认背景；
- 可复用层与方案专属层；
- 必须保留的比例、位置、连接和颜色；
- 本轮只修改的层；
- 需要验证的最终场景。

若没有历史版本，再从产品事实建立新方向。若已有确认，不重新从零发散。

### 3. 先展开主体图案层

主体先在中性白底或黑白条件下设计，回答：

1. 它表达的产品关系是什么；
2. 第一眼主体是什么；
3. 唯一记忆点在哪里；
4. 轮廓、正负形和内部细节如何共同工作；
5. 在 24/32/48/64 px 是否仍成立；
6. 更换背景后是否仍保持身份。

主体未成立前，不用键帽、渐变、高光或复杂背景补救。新方向的差异必须来自语义或构形机制，不来自换色。

### 4. 锁定主体，再展开背景层

背景单独设计和检查，回答：

1. 它是纯底色、排列背景、单个容器还是方案自身的一部分；
2. 是否必须满幅，外轮廓和圆角由谁控制；
3. 纹理在什么距离仍可见；
4. 明度、颜色和材质是否始终低于主体层级；
5. 哪些主体能共用，哪些主体必须保留自己的专属载体；
6. 去掉主体时是否仍无裁切、白边、脏像素或残缺边界。

背景探索使用已锁定主体做层级测试，但不能借此改写主体。背景是独立资产时必须保留空白母版。

### 5. 建立组合矩阵

将当前主体与允许的背景组合：

```text
主体图案层 × 背景层 = App icon 组合
App icon 组合 × 验证场景 = 评审资产
```

不是所有背景都必须适配所有主体；先记录适用关系。用户明确要求全量组合时，逐项生成，不用代表性样例替代。组合时分别控制背景满幅和主体光学比例。

### 6. 一次只校准一层

- 调整主体时，固定背景；
- 调整背景时，固定主体；
- 调整组合比例时，不同时改变形状和材质；
- 需要整体改变时拆成连续版本，使改善来源可判断。

反馈记录必须写明 `subject`、`background`、`composition` 或 `context`。若改背景导致主体关系丢失，先回退背景；若改主体需要重新适配背景，另开下一步，不合并成一次不透明修改。

### 7. 进入场景验证

组合成立后再进入小尺寸、单色/反白、完整手机主屏、HTML 与 Figma。场景只验证真实使用效果，不承担修复基础设计的职责。

## Agent 的默认输出

当用户没有指定流程时，Agent 至少给出或维护这些中间结果：

1. **Reference Map**：每张参考影响哪一层；
2. **Layer Map**：主体、背景、可复用关系和禁改项；
3. **Design Brief**：产品事实、调性、场景和风险；
4. **Subject Directions**：先评审主体图案；
5. **Background Directions**：主体锁定后评审背景；
6. **Combination Matrix**：哪些组合需要生成和验证；
7. **Review Pack**：大图、小尺寸、主屏与必要说明；
8. **Decision Ledger**：人工确认、保留/搁置与下一步。

这些内容可以体现在项目文件、评审 HTML 或 Figma 中，不要求每次都向用户展示全部过程。对外评审只呈现决策需要的部分。

## 任务模式

- **新 Logo**：完整执行 Reference Map → 主体 → 背景 → 组合 → 场景。
- **只有主体修改**：读取 Layer Map，锁定背景，只修改主体并重新跑组合/场景。
- **只有背景修改**：锁定主体，单独输出空白背景与组合对照。
- **只做材质/配色**：先判断材质属于哪一层，再保持另一层不变。
- **只做评审/Figma**：不重新设计，但必须检查两层来源、组合完整性和场景清晰度。

## 停止条件

- 主体语义或轮廓尚未通过，不进入复杂背景和材质；
- 背景抢主体或改变设计关系，退回背景层校准；
- 参考用途不清但会产生完全不同设计方向，先询问；
- 只是缺少流程说明时，不询问，直接使用本方法论推进；
- 人工确认绑定具体版本；新修改产生新版本并重新评审。
