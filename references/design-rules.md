# 设计与视觉校验

## 三种规则强度

工程不变量、用户明确的风格约束、Agent 探索假设分别记录。本 Skill 服务于小红书产品调性，遵守 xiaohongshu-taste.md；Spark 的无嘴 Wink 等局部选择不能推为所有产品的造型。历史近黑电光偏好已被新要求取代。

## 构形与适配

- 定调先于造型：从产品文档提取有来源的关键词，把品牌/平台调性要求另列，再将其转译为轮廓、比例、色彩和质感假设。不能以 Agent 喜好的“科技感”代替品牌调性；没有实际参考时标明假设。
- 顶层先拆成主体图案层与背景层。主体先检验品牌含义、识别和独特性；背景负责底色、容器、排列、材质和承托。颜色与材质归入实际作用的层。在同一个主体上比较背景，不用材料变化掩盖主体表意不足。字母可以成为结构，但是否足以表达品牌需要独立判断。
- 不强迫全部主体复用同一背景载体。先记录适用关系：公共背景、方案专属背景或不适用。背景单独保留空白资产，组合稿不能替代背景母版。
- 展示序号按当前保留方案连续生成；稳定资产 ID、历史版本和分享锚点不随序号重用。与设计师已改过的 Figma 标题核对，不用旧图层名覆盖新顺序。

- 分清独立图形标、完整 App icon、图标+字标组合。不要把带字标画布整体缩成手机图标；提供单独 icon 源或显式裁切参数。
- contain 用于需要呼吸空间的独立火种等；full-bleed 用于构图本来占满容器的键位/键帽。外轮廓由最终占位遮罩控制，贴外缘的内部元素不再单独倒圆角，以免出现碎缺口。
- 正负形是具体连续区域，不是“中心补一个通用四角星”。标出完整轮廓和延伸范围，区分内部平滑曲线、尖端和外边界。修改前先解释理解，必要时用局部对照，不反复盲猜。
- 小尺寸以实际 24/32/48/64 px 查看，检查间隙闭合、负形细线化、描边丢失、与桌面其他图标的重量。放大截图不等于手机可识别；需要光学修正时另存小尺寸版。
- 检查透明外沿、脏像素、白边、裁切接缝和内置留白。object-fit 或扩大缩放不能自动修复源图。不要把裁掉缺陷当成几何精修。

## 质感与配色

- 先确认背景与主符号层级。纯色是默认起点；渐变仅在用户明确允许且不改变设计关系时使用，必须限制范围、色数和对比。轻质感优先克制的离散色面/窄边。禁止厚倒角、金属强反光、颗粒噪声和大阴影。
- “看着脏”先排查噪点、灰雾、残留边缘、叠加滤镜和过多光源；不要再叠一层光效来遮盖。
- 参考中的颗粒、大幅光晕可能适合海报，不适合 64 px 图标。提取色彩关系，不照搬全部材质。
- 用角色组织纯色配色：主底色、识别色、局部强调、符号色。历史电光与紫光稿仅归档，不作为新方向。先评审形状再扩色。
- 换色必须检查轮廓漂移、字形变化、反射变形。生成器不能保证只改颜色，即便提示词这样要求；偏移明显时标成探索稿或重做。
- `filter-preview` 是显示探索；`grayscale-preview` 是灰度检查；`monochrome-artwork` 才是按黑/白结构重构且人工验收的单色资产。全涂黑会丢掉层级，不叫适配。
- CSS 滤镜无法直接作为 Figma 图片填充复现，先栅格化为独立图像并核对网页效果，或在浏览器导出当前渲染像素。不得静默漏掉旧滤镜。

## 概念文案与反馈

文案按“产品使用关系 → 图形如何表达 → 该方向取舍”写。火种可以表达表达的起点；键位底层与 S 可以表达按需辅助；拟人键帽可以表达回应感。不要只罗列“像素/星芒/生长”，也不要虚构 PRD 功能。

> 对象：智能键帽 v5；改：右眼短横上扬 Wink；保留：左眼胶囊、青蓝外框、深蓝内面、铺满比例；不添加嘴/星星/底座分界；验证：64 px 表情与原稿轮廓叠对。

如果设计师让“保留两个方案”，保留两条版本分支。如果让“搁置/删除方案”，从当前评审隐藏并保留历史证据，不删除所有原图。新的明确指示优先于早期 AI 假设（例如最初避开通用机器人，并不阻止后来经设计师决定探索智能角色）。
