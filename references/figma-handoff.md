# 网页确认与 Figma 交接

## 可运行入口

网页先确认当前版本与配色，再点“同步到 Figma…”。本 Skill v1 导出自包含 JSON（选中项、文本、源哈希、所见 PNG、手机场景 PNG、人工自述确认），并说明后续步骤。附件 `figma-plugin/manifest.json` 可在 Figma 桌面版作为开发插件导入；选择 JSON 后点击“导入确认方案”。插件仅向当前文件新增评审板，不覆盖旧图层。

这是两步交接，不是网页直接远程写入。下载后网页保持“同步包已生成，等待 Figma 导入”；仅插件完成后显示创建节点。Figma 登录、文件编辑权限和开发插件安装由宿主提供。随技能附带的源码与自动化测试不等于已经在用户 Figma 中安装/实测。

## 原生 Agent 同步

当环境有 Figma 写入能力时，必须先加载当时可用的 Figma 使用/生成 Skill。解析用户提供 URL 的 file key 与 node id，不凭当前打开页面、文件标题或旧同步记录猜目标。先读取目标节点与现有结构；按方案/版本/背景创建节点；图片与说明分层；使用实际字体；回读数量、顺序、标题和截图，记录文件与 node ID。不要把工具特有 API 与桌面插件 API 混用。

普通网页不能获取或复用 Agent 的 MCP 会话。未来需要真正跨端“一键同步”时，必须有经过授权的服务/插件桥接：请求包含项目、版本、配色、目标文件、快照哈希与幂等键；响应包含 job ID；任务状态为 pending/running/succeeded/failed，成功必须有实际文件与节点 ID。由真实接入能力决定实现，不能填虚假 endpoint、向公开页面放 token，或把打开 Figma URL 当作同步。

## 内容保真

- 旧滤镜在浏览器 Canvas 栅格化，输出与页面同源；不要向插件传 CSS filter 后宣称已生效。
- Logo PNG 为位图。标题/说明在插件中可编辑；此版本手机场景合成为图片，忠实但不分层。若需要分层手机、原生矢量或组件，使用 Agent 原生路线另做并核验。
- 确認记录绑定版本、配色和资产哈希；确认后切换配色必须重新确认。修改内容生成新 revision。
- 插件重复导入同一 snapshotId 时回到已有板；部分失败删除本次新建板，保留全部既有内容，可重试。
- 多位评审者：网页选择是本机状态，导出 JSON 才可汇总；没有服务端时不能说已保存给团队。
- 手机主屏使用高清原始/分层素材；写入前核对除目标 Logo 外的所有界面内容清晰。所有当前组合都需要对应主屏，不能只同步个别方案。
- 主体与背景分别控制：背景层铺满 icon 容器，主体按该方向光学比例放置。组合图过小或背景未铺满时，应修正源组合而不是只在 Figma 中机械放大整图。
- 面向决策者的 Figma 画板与 HTML 保持同一精简内容模型，不同步过程性辩解、对话提示或已经删除的 QA 章节。

交付时写清实际做到了哪一步：模板生成、包导出、插件准备、真实导入、回读验收、正式矢量交付，不合并成一句“全部完成”。
