# Spark 实践来源与成熟度

> 本文记录 2026-09-17 至 2026-09-20 的历史轨迹，不是固定风格许可。减科技感、避免写实、克制颜色和材质是稳定取向；是否使用轻微渐变由具体对象和最新人工要求决定。新设计依据见 `xiaohongshu-taste.md`。

来源是本次对话中的设计师反馈，以及项目 `review/` 下的适配、质感、配色、Figma 同步记录。只经过 Spark 一项真实产品的多轮试用；这是可运行 v1，不宣称已在多行业验证或已测得效率提升。

| 实际反馈/转折 | 应沉淀的机制 | 适用边界 |
|---|---|---|
| 火种不能占满；另两种本就占满 | 每方向独立 icon 适配参数，统一场景而非统一 padding | 通用 |
| 外缘键粒圆角奇怪 | 外层遮罩与内部曲线分别校验；触边元素不多做圆角 | 对应构形 |
| 星芒负形太细 | 实际小尺寸与手机场景优先于放大图 | 通用 |
| 反色更奇怪，回原版 | 受控分支、可回看；不把试验替换成已确认稿 | 通用 |
| 要把原负形整块凸出，别另画星星 | 先锁语义区域与几何，再改材料层 | 通用 |
| 太拟物、老气、很脏 | 材质层级和噪声检查；必要时退回纯色或只保留局部窄边 | 通用 |
| 同时保留两个键帽方向 | 允许并行保留，不强制唯一选择 | 通用 |
| 实心 S、轻渐变、不同于参考 | 分离字形、材料、配色；参考作为语言而非复制 | 通用 |
| 智能键帽要科技感；铺满 | 场景布局与造型语义共同评审 | Spark 偏好 |
| 回原版只改 Wink，无嘴 | 明确改动与禁改列表 | 通用方法 / 项目造型 |
| 原色土气，给六张新参考 | 从色彩关系提炼新方向；允许推翻初始 AI 色彩假设 | 通用 |
| 纯黑不等于全部涂黑 | 灰度预览与生产单色分级 | 通用 |
| 新旧滤镜配色都进 Figma | 枚举导出清单、核对数量及图像哈希 | 通用 |
| 本地网页别人打不开 | 区分本机 HTML、公开发布、Figma 文件权限 | 通用 |
| 星星与底座衔接被缩小 | 锁定连接宽度、进入深度和母版相对位置 | 通用 |
| 指定只换嘴但整图变化 | 确定性局部替换，并检查补丁外像素差异 | 通用 |
| 背景“太灰” | 以白为主，仅用轻色差维持键盘排列 | Spark 表现 / 通用层级判断 |
| 超轻材质看不出变化 | 在真实缩略图尺寸校验可见性，不用参数变化冒充视觉变化 | 通用 |
| 质感导致原设计关系丢失 | 回到已确认母版，材质只进入关键细节 | 通用 |
| 背景未铺满、主体过小 | 背景与主体分层控制；逐方案做光学尺寸 | 通用 |
| 只有个别主屏方案 | 主体 × 背景建立完整场景矩阵 | 通用 |
| 主屏除目标 Logo 外模糊 | 保留高清整屏，只替换原生 icon slot | 通用 |
| Figma 写到非指定位置 | 使用用户 URL 的 file key/node id 并写后回读 | 通用 |
| 评审页解释词过多 | 对外页面只保留方案、必要理念、差异和风险 | 通用 |

最初 Workflow Core 强制三方向、每方向四张及唯一方案；后续真实迭代出现保留多方案和精准局部修改。这些固定数量不进入新 Skill 的强制规则。当前 validator 只检查实际记录与资产完整性，不再用固定数量冒充设计质量。

后续组长评审修正了调性：现有多方案过于科技、写实或通用 AI，S 未传达品牌含义；要求先从产品提取关键词并结合小红书调性，再拆成基础图形与外层呈现。由此增加“先定调、先验证品牌图形，再比较键帽等呈现”的规则。小红书调性是 Spark 当轮要求，不上升为所有品牌的风格规范。早期电光配色仍作历史记录，不能继续充当当前默认方向。移除旧 02 后，当前展示顺序为 01 火种、02 键位 S、03 薄型键帽、04 立体键帽、05 Wink；稳定资产编号仍为 1/3/4/5/6。

Round 83–84 证明了精确连接与局部嘴形不能依赖整图重生成；Round 85–86 从灰蓝遮罩退回珍珠白，确认背景色必须服务键盘结构和主体层级；Round 87–91 从整面轻材质经历“太重—太轻看不见—平面色块—黑银缎面”，建立可见性与克制之间的尺度；Round 92 将五主体与三背景展开为组合矩阵，并暴露主体比例、背景满幅、手机主屏清晰度、全量覆盖和指定 Figma node 写入问题。

已验证经验：统一场景能显露填充、小尺寸与清晰度问题，版本化能避免覆盖，Figma 可接收位图与可编辑说明。待后续项目验证：跨产品可迁移性、设计师使用成本、同步插件真实运行与审美一致性。把每次真实失败补成窄规则，不无限累加风格禁令。
